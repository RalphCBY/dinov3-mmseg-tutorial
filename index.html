本文档是 mmseg_dinov3 教程包的详细说明。

本教程适合以下读者:

  • 没有系统接触过 AI 或深度学习的遥感、测绘、地理信息、无人机影像方向学生。
  • 已经有自己的影像和逐像素标签，希望使用现成代码训练语义分割模型的人。
  • 需要理解 DINOv3、MMSegmentation、UAVid 数据格式、训练、测试、可视化和评估指标的人。

学完本教程, 你将能够:

  • 知道语义分割任务到底在做什么。
  • 知道 DINOv3 在这里扮演什么角色。
  • 能把自己的影像和标签整理成可运行的数据格式。
  • 能从零创建或激活一个兼容的 MMSegmentation 运行环境，并跑通训练、测试和单图推理。
  • 能读懂 mIoU、mAcc、aAcc、per-class IoU 等评估结果。

你拿到压缩包并解压后，教程包根目录记作:

mmseg_dinov3/

教程包里的可运行 MMSeg 项目目录记作：

mmseg_dinov3/mmsegmentation-main/

所有 python train.py、python test.py、python predict.py 命令都应该在这个运行目录里执行：

cd /path/to/mmseg_dinov3/mmsegmentation-main
export PYTHONPATH="$PWD:$PYTHONPATH"

其中 /path/to/mmseg_dinov3 表示你自己电脑或服务器上解压后的实际位置。

mmsegmentation-main/mmseg/ 已包含从服务器工作项目复制来的完整 MMSeg Python 源码目录，你安装好兼容的 OpenMMLab/MMSeg 环境后，可以直接进入本包的 mmsegmentation-main/ 运行教程命令。本教程包的 ckpt/ 已包含 ViT/ConvNeXt 官方预训练权重和对应的 UPerNet 微调 checkpoint；完整 UAVid 数据、SLURM 日志和训练输出不包含在包内，需要按教程单独指定路径。

本教程的资源构成如下:

环境依赖由 conda/pip 安装
MMSeg Python 源码由本包自带
教程代码、config、sample data 也由本包自带
ckpt/ 内置 ViT/ConvNeXt 官方预训练权重和对应 UPerNet 微调 checkpoint；正式数据集由使用者自己提供路径

不需要再单独下载 MMSegmentation 源码包。只要环境中有兼容的 PyTorch、MMCV、MMEngine、OpenMIM/MMSeg 相关依赖，并且命令是在本包 mmsegmentation-main/ 根目录下运行，Python 会优先使用本包内的 mmseg/ 源码。

0.1 路径写法约定¶

本教程所有操作路径都使用相对路径或占位路径，方便你替换成自己机器上的实际位置。

路径约定如下: | 名称 | 写法 | 含义 | |---|---|---| | 教学包根目录 | mmseg_dinov3/ | 你解压后得到的文件夹 | | 代码运行目录 | mmseg_dinov3/mmsegmentation-main/ | 包含 train.py/test.py/predict.py 的目录 | | DINOv3 ViT 权重 | ../ckpt/dinov3_vitb16_pretrain_lvd1689m-73cec8be.pth | 包内已放入的官方 DINOv3 ViT-B/16 权重，从 mmsegmentation-main/ 运行时可直接使用 | | ViT 分割 checkpoint | ../ckpt/dinov3_vitb_upernet.pth | 包内已放入的 ViT + UPerNet 微调 checkpoint，可直接 test/predict | | ConvNeXt 分割 checkpoint | ../ckpt/dinov3_convnext_upernet.pth | 包内已放入的 ConvNeXt + UPerNet 微调 checkpoint，可直接 test/predict | | DINOv3 ConvNeXt 官方预训练权重 | ../ckpt/dinov3_convnext_base_pretrain_lvd1689m-801f2ba9.pth | 包内已放入的官方 DINOv3 ConvNeXt-Base 权重，从 mmsegmentation-main/ 运行时可直接使用 | | 完整 UAVid 数据 | /path/to/uavid_v1.5_official_release_image | 你自己的完整数据集路径 |

进入运行目录：

cd /path/to/mmseg_dinov3/mmsegmentation-main
export PYTHONPATH="$PWD:$PYTHONPATH"

上面的 /path/to/mmseg_dinov3 是占位符。请替换成你实际解压的位置，例如:

cd ~/Downloads/mmseg_dinov3/mmsegmentation-main

或：

cd /data/user/project/mmseg_dinov3/mmsegmentation-main

0.2 不需要 sbatch¶

sbatch 是 SLURM 集群提交后台任务用的命令。教学包本身不依赖 sbatch。没有集群环境时，直接在终端运行:

python train.py ...
python test.py ...
python predict.py ...

如果机器上有 GPU，建议指定一张 GPU：

export CUDA_VISIBLE_DEVICES=0

如果没有 GPU，只想验证 predict.py 能不能跑，可以用：

--device cpu

但注意：CPU 预测会很慢，训练和 3840 x 2160 全尺寸滑窗预测都建议使用 GPU。

0.3 三个入口脚本分别做什么¶

🎓
学

train.py

用 Images + Labels 训练语义分割模型

输出 → work_dirs/iter_*.pth

📊
评

test.py

用 Images + Labels 评估已训练模型的精度

输出 → mIoU / mAcc / aAcc

🖼️
用

predict.py

只用 Images 生成预测图,不计算 mIoU

输出 → overlay / pred_color / pred_id

脚本 是否需要标签 是否需要训练好的分割 checkpoint 作用 主要输出
train.py 需要 不需要 训练语义分割模型 work_dirs/.../iter_*.pth、训练 log、验证指标
test.py 需要 需要 在有标签的数据上评估模型精度 aAcc、mIoU、mAcc、per-class IoU
predict.py 不需要 需要 对单张图或图片文件夹做预测 overlay/、pred_color/、pred_id/

一句话区分：

train.py   用 Images + Labels 学模型。
test.py    用 Images + Labels 评估一个已训练模型。
predict.py 只用 Images 生成预测图，不计算 mIoU。

0.4 先做最小自检¶

第一步，确认当前目录正确：

pwd

ls projects/UAVid_dataset/configs

期望看到：

train.py
test.py
predict.py
convnext_dinov3_uavid_512_default.py
vit_dinov3_uavid_512_default.py

第二步，确认 Python 导入的是本包自带的 mmseg：

python - <<'PY'
import mmseg
print(mmseg.__file__)
PY

期望输出类似：

/path/to/mmseg_dinov3/mmsegmentation-main/mmseg/__init__.py

如果输出是：

.../site-packages/mmseg/__init__.py

说明你导入了 conda 环境里安装的 mmseg，不是教学包里的源码。请重新执行：

cd /path/to/mmseg_dinov3/mmsegmentation-main
export PYTHONPATH="$PWD:$PYTHONPATH"

第三步，检查 sample data：

python tools/check_uavid_dataset.py sample_data/uavid_v1.5_official_release_image

期望输出类似：

image-label pairs: 30
missing labels: 0
unknown label colors: {}
Dataset check passed.

如果 image-label pairs 是 0，通常是传错了路径。这里要传包含 uavid_train、uavid_val、uavid_test 的数据根目录，不要传某一个单独的 seq16 目录。

0.5 准备权重和 checkpoint 变量¶

从 mmsegmentation-main/ 目录运行时，包内 ckpt/ 的相对路径是：

../ckpt/

教程包内已按 2026-05-29 最新 ckpt/ 目录同步检查到四个 .pth 文件。这里只关注 .pth 权重文件；如果 macOS 打包时带入 .DS_Store 这类隐藏文件，教学中可以忽略。

../ckpt/dinov3_vitb16_pretrain_lvd1689m-73cec8be.pth
../ckpt/dinov3_convnext_base_pretrain_lvd1689m-801f2ba9.pth
../ckpt/dinov3_vitb_upernet.pth
../ckpt/dinov3_convnext_upernet.pth

它们的作用不同：

文件 大小约 类型 用途
dinov3_vitb16_pretrain_lvd1689m-73cec8be.pth 327M DINOv3 ViT-B/16 官方预训练 backbone 权重 ViT 训练、ViT test/predict 初始化 backbone
dinov3_convnext_base_pretrain_lvd1689m-801f2ba9.pth 338M DINOv3 ConvNeXt-Base 官方预训练 backbone 权重 ConvNeXt 训练、ConvNeXt test/predict 初始化 backbone
dinov3_vitb_upernet.pth 803M ViT + UPerNet 已微调分割 checkpoint 直接跑 ViT 的 test.py 或 predict.py
dinov3_convnext_upernet.pth 733M ConvNeXt + UPerNet 已微调分割 checkpoint 直接跑 ConvNeXt 的 test.py 或 predict.py

解压教学包后，可以在 mmsegmentation-main/ 目录下用下面的命令自检权重是否齐全：

ls -lh ../ckpt/*.pth

预期能看到上表四个文件。不同操作系统显示的大小可能有少量差别，但文件名必须一致。

推荐先设置这些变量：

export DINO_VIT_CKPT=../ckpt/dinov3_vitb16_pretrain_lvd1689m-73cec8be.pth
export DINO_CNN_CKPT=../ckpt/dinov3_convnext_base_pretrain_lvd1689m-801f2ba9.pth
export VIT_SEG_CKPT=../ckpt/dinov3_vitb_upernet.pth
export CNN_SEG_CKPT=../ckpt/dinov3_convnext_upernet.pth

设置后检查文件是否存在：

ls "$DINO_VIT_CKPT"
ls "$DINO_CNN_CKPT"
ls "$VIT_SEG_CKPT"
ls "$CNN_SEG_CKPT"

请注意两类 checkpoint 的区别:

checkpoint 例子 用在哪里
DINOv3 官方预训练权重 dinov3_vitb16_pretrain_*.pth、dinov3_convnext_base_pretrain_*.pth 传给 model.backbone.pretrained=...
训练后的分割模型权重 dinov3_vitb_upernet.pth、dinov3_convnext_upernet.pth、work_dirs/*/iter_*.pth 传给 --checkpoint ...

常见错误是把 DINOv3 官方权重传给 --checkpoint。这是不对的，因为 --checkpoint 需要的是已经训练过分割头的 MMSeg checkpoint。

0.6 ViT 版本：训练、测试、预测¶

设置 config 和输出目录：

CONFIG_VIT=projects/UAVid_dataset/configs/vit_dinov3_uavid_512_default.py
WORK_VIT=work_dirs/vit_smoke

0.6.1 ViT 训练¶

先跑一个 5 iter 的短训练。这个命令只用于验证流程，不代表最终精度。

python train.py \
  --config "$CONFIG_VIT" \
  --work-dir "$WORK_VIT" \
  --cfg-options \
    model.backbone.pretrained="$DINO_VIT_CKPT" \
    train_dataloader.batch_size=2 \
    train_dataloader.num_workers=0 \
    train_dataloader.persistent_workers=False \
    val_dataloader.batch_size=1 \
    val_dataloader.num_workers=0 \
    val_dataloader.persistent_workers=False \
    test_dataloader.batch_size=1 \
    test_dataloader.num_workers=0 \
    test_dataloader.persistent_workers=False \
    train_cfg.max_iters=5 \
    train_cfg.val_interval=5 \
    default_hooks.checkpoint.interval=5 \
    default_hooks.logger.interval=1 \
    param_scheduler.0.end=1 \
    param_scheduler.1.begin=1 \
    param_scheduler.1.end=5

成功时，log 中会看到 DINOv3 ViT 权重加载信息：

[DINOv3] Loading ViT backbone weights from: ../ckpt/dinov3_vitb16_pretrain_lvd1689m-73cec8be.pth
[DINOv3] Backbone keys: model=188, ckpt=188, matched=188
[DINOv3] All 188 keys matched perfectly
[DINOv3] ViT backbone weights loaded successfully.
[DINOv3] Backbone dinov3_vit16_base is frozen.

也会看到训练迭代：

Iter(train) [1/5]  loss: ...
Iter(train) [5/5]  loss: ...
Iter(val) ... aAcc: ... mIoU: ... mAcc: ...

期望输出文件：

work_dirs/vit_smoke/
  iter_5.pth
  last_checkpoint
  20xxxxxx_xxxxxx/
    20xxxxxx_xxxxxx.log
    vis_data/scalars.json

如果出现下面错误：

ValueError: Expected more than 1 value per channel when training, got input size torch.Size([1, 512, 1, 1])

通常是 UPerNet 的 PPM 分支使用 BatchNorm，而训练 batch size 设置成了 1。请使用：

train_dataloader.batch_size=2

或更大。

0.6.2 ViT 测试¶

训练得到 iter_5.pth 后，测试它：

python test.py \
  --config "$CONFIG_VIT" \
  --checkpoint "$WORK_VIT/iter_5.pth" \
  --work-dir "$WORK_VIT/test_iter5" \
  --show-dir "$WORK_VIT/show_iter5" \
  --cfg-options model.backbone.pretrained="$DINO_VIT_CKPT"

如果你只是想直接体验 test 流程，也可以不先训练，直接使用包内已经微调好的 ViT + UPerNet checkpoint：

python test.py \
  --config "$CONFIG_VIT" \
  --checkpoint "$VIT_SEG_CKPT" \
  --work-dir "$WORK_VIT/test_packaged_ckpt" \
  --show-dir "$WORK_VIT/show_packaged_ckpt" \
  --cfg-options model.backbone.pretrained="$DINO_VIT_CKPT"

成功时会看到：

Iter(test) [10/10]
aAcc: ...
mIoU: ...
mAcc: ...

输出解释：

aAcc: overall pixel accuracy
mIoU: mean Intersection over Union, 语义分割最常用主指标
mAcc: mean class accuracy
per-class IoU: 每一类自己的 IoU

如果指定了 --show-dir，可视化结果会保存到：

work_dirs/vit_smoke/show_iter5/

只训练 5 iter 时，mIoU 可能很低。这不是失败，只说明模型还没有真正训练充分。

predict.py 不需要标签，只需要图片和分割 checkpoint。

单图预测：

python predict.py \
  --config "$CONFIG_VIT" \
  --checkpoint "$WORK_VIT/iter_5.pth" \
  --input "$IMAGE" \
  --out-dir "$WORK_VIT/predict_000000" \
  --device cuda:0 \
  --slide \
  --crop-size 512 512 \
  --stride 256 256 \
  --cfg-options model.backbone.pretrained="$DINO_VIT_CKPT"

文件夹预测：

IMAGE_DIR=sample_data/uavid_v1.5_official_release_image/uavid_test/seq34/Images

python predict.py \
  --config "$CONFIG_VIT" \
  --checkpoint "$WORK_VIT/iter_5.pth" \

--checkpoint "$VIT_SEG_CKPT"

完整例子：

python predict.py \
  --config "$CONFIG_VIT" \
  --checkpoint "$VIT_SEG_CKPT" \

CPU 预测示例：

python predict.py \
  --config "$CONFIG_VIT" \
  --checkpoint "$WORK_VIT/iter_5.pth" \
  --input "$IMAGE" \
  --out-dir "$WORK_VIT/predict_cpu" \
  --device cpu \
  --slide \
  --crop-size 512 512 \
  --stride 256 256 \
  --cfg-options model.backbone.pretrained="$DINO_VIT_CKPT"

成功时会打印：

Using model.test_cfg={'mode': 'slide', 'crop_size': (512, 512), 'stride': (256, 256)}
.../000000.png input=3840x2160 pred=3840x2160 -> ...

这里要特别说明:512 x 512 是滑窗 crop 大小，不是最终输出大小。最终预测图尺寸应该和输入图一样。对于 UAVid 原图，常见输出是：

0.9 ConvNeXt 权重 warning 怎么解释¶

加载某些微调后的 ConvNeXt 分割 checkpoint 时，MMSeg 可能提示：

unexpected key: backbone.backbone.norms.3.weight
unexpected key: backbone.backbone.norms.3.bias

这两个 warning 在本教程包里是非致命的。原因是某些 checkpoint 同时保存了最终 norm 的旧别名 norms.3.* 和当前模型实际使用的 norm.*。服务器上已检查过，这两个旧别名是冗余 key；真实模型需要的 canonical key 可以正常加载。

判断权重是否真正加载成功，应看 DINOv3 backbone 日志：

[DINOv3] Backbone keys: model=342, ckpt=342, matched=342
[DINOv3] All 342 keys matched perfectly

以及 load checkpoint from ... 后是否继续进入 Iter(train)、Iter(test) 或预测输出。

5. DINOv3 的作用¶

DINOv3 是一种自监督视觉基础模型。简单说，它先在大量无标签图像上学习通用视觉特征，然后可以迁移到下游任务。

本教程中, DINOv3 的角色是: - DINOv3 不直接输出语义分割图。 - DINOv3 负责把输入影像编码成高层视觉特征。 - UPerNet 负责把这些特征转换成逐像素类别预测。

你可以这样理解:

DINOv3: 负责看懂图像内容
UPerNet: 负责把看懂的内容画成语义分割结果

教程配置中使用的是 DINOv3 ViT-B/16 风格的 backbone wrapper：

mmseg/models/backbones/dinov3_BACKBONE.py

主配置里对应字段是：

model = dict(
    backbone=dict(
        pretrained=pretrained,
        freeze=True,
        out_indices=1,
    )
)

关键点：

  • pretrained 是 DINOv3 权重路径。
  • freeze=True 表示训练语义分割时冻结 DINOv3 backbone，只训练分割头等下游模块。
  • 字段名是 freeze=True，不是 frozen=True。
  • out_indices=1 是当前本地 DINOv3 wrapper 兼容之前下游配置的写法，wrapper 会处理给 UPerNet 需要的多层特征形式。

6. 什么是语义分割¶

语义分割就是给图里每一个像素分配一个类别。下面是 UAVid 的一张无人机原图和它的逐像素彩色标签:

图像分类回答：

这张图里有什么？

目标检测回答：

图里有哪些目标？每个目标的框在哪里？

语义分割回答：

图里的每个像素分别属于什么类别？

例如 UAVid 语义分割中，一张无人机影像会被分成：

  • building
  • road
  • tree
  • low_vegetation
  • moving_car
  • static_car
  • human
  • background_clutter

最终预测图与原图大小相同，每个像素是一个类别 id。

7. UAVid 类别和颜色¶

当前教程使用 UAVid 的 8 类设置。

class id class name RGB label color 中文理解
0 building [128, 0, 0] 建筑物
1 road [128, 64, 128] 道路
2 tree [0, 128, 0] 树木
3 low_vegetation [128, 128, 0] 低矮植被
4 moving_car [64, 0, 128] 运动车辆
5 static_car [192, 0, 192] 静止车辆
6 human [64, 64, 0] 行人
7 background_clutter [0, 0, 0] 背景杂类

标签可以有两种形式：

  1. RGB 彩色 label mask。
  2. 单通道 class-id label mask。

当前 transform UAVidColorToId 可以把 RGB 彩色标签转换成单通道 class id。若输入已经是单通道 class id，它会保持单通道形式。

未知颜色会被转换为：

255

在 MMSegmentation 中，255 是 ignore index，表示这个像素不参与 loss 和指标计算。

这个文件注册了自定义数据集：

真实读取逻辑是：

base_dir = data_root / split
image_dir = base_dir / seq / Images
label_dir = base_dir / seq / Labels

因此，如果 config 里写：

data_root = 'sample_data/uavid_v1.5_official_release_image'

那么实际读取路径就是：

sample_data/uavid_v1.5_official_release_image/uavid_val/seq16/Images/*.png
sample_data/uavid_v1.5_official_release_image/uavid_val/seq16/Labels/*.png

这个写法与 MMSeg 常见的 data_prefix=dict(img_path=..., seg_map_path=...) 不同。当前教程包应当沿用 UAVIDDataset(data_root, split, sequences) 的逻辑，不建议在教程里改成泛化的 data_prefix 示例，否则会和当前代码不一致。

10.2 tools/uavid_color_to_id.py¶

这个文件注册了 pipeline transform：

UAVidColorToId

它的作用是：

RGB color mask -> single-channel class id mask

例如：

[128, 64, 128] -> class id 1 -> road

训练前，MMSeg pipeline 会先加载 RGB label，然后通过这个 transform 转成 class id。这样你可以用彩色标签进行标注和查看，同时模型内部仍然使用 class id 计算 loss。

10.3 mmseg/models/backbones/dinov3_BACKBONE.py¶

这个文件提供 DINOv3 backbone wrapper，让 DINOv3 能被 MMSeg 模型调用。

核心类：

DINOv3ViT
DINOv3ConvNeXt

本教程提供两种 backbone 配置：

DINOv3ViT       # ViT 版本
DINOv3ConvNeXt  # CNN/ConvNeXt 版本

它们负责：

  • 构建 DINOv3 ViT 或 DINOv3 ConvNeXt backbone。
  • 加载 DINOv3 官方预训练权重。
  • 把 DINOv3 输出转换成 UPerNet 可用的 feature format。
  • 在 freeze=True 时冻结 backbone 参数。

训练日志中正常加载 DINOv3 权重时，会看到类似：

[DINOv3] All 188 keys matched perfectly
[DINOv3] ViT backbone weights loaded successfully.
[DINOv3] Backbone dinov3_vit16_base is frozen.

这说明 backbone 权重完整读入。

ConvNeXt 版本正常加载时会看到类似：

[DINOv3] Backbone keys: model=342, ckpt=342, matched=342
[DINOv3] All 342 keys matched perfectly
[DINOv3] Backbone weights loaded successfully.
[DINOv3] Backbone dinov3_convnext_base is frozen.

11.3 教学解释¶

可以用下面的比喻来理解:

DINOv3 像一个已经学过大量图像知识的观察者，负责提取图像中的道路、建筑、植被、车辆等视觉线索。
UPerNet 像一个画图的人，负责把这些视觉线索转换成每个像素的类别颜色。
MMSegmentation 是训练和评估这套系统的工程框架。

CNN_SEG_CKPT ../ckpt/dinov3_convnext_upernet.pth ConvNeXt + UPerNet 微调分割 checkpoint
DINO_CNN_CKPT ../ckpt/dinov3_convnext_base_pretrain_lvd1689m-801f2ba9.pth ConvNeXt 官方预训练 backbone 权重

设置方式：

export DINO_CNN_CKPT=../ckpt/dinov3_convnext_base_pretrain_lvd1689m-801f2ba9.pth

训练和测试时，官方预训练权重通过 config override 传入：

--cfg-options model.backbone.pretrained="$DINO_CNN_CKPT"

20. 如何适配自己的数据集和分割头¶

最推荐的入门方式：让自己的数据集尽量模仿 UAVid 文件结构。

例如：

my_dataset/
  uavid_train/
    seq1/
      Images/*.png
      Labels/*.png
  uavid_val/
    seq16/
      Images/*.png
      Labels/*.png
  uavid_test/
    seq34/
      Images/*.png
      Labels/*.png

这样只需要改：

data_root
sequences
classes
palette
num_classes

这一条是给初学者的最短路径。它的前提是：你的数据能整理成 split/seq/Images 和 split/seq/Labels 这种结构，并且每张图与标签同名。如果你的数据不是这种目录结构，例如所有图片在一个文件夹、标签文件名有后缀、标签存在 JSON/GeoJSON/shapefile 中，或者 train/val/test 用 txt 列表管理，就不要硬套 UAVIDDataset。那时更清楚的做法是新建一个 dataset class，并在 config 里注册它。

可以把适配分成三档：

情况 推荐做法 需要改的文件
数据目录和 UAVid 类似，只是路径不同 直接改 data_root 和 sequences projects/UAVid_dataset/_base_/datasets/uavid.py 或命令行 --cfg-options

20.1 如果只是换数据路径¶

只改数据路径：

DATA_ROOT=/absolute/path/to/my_dataset

python train.py \
  --config projects/UAVid_dataset/configs/vit_dinov3_uavid_512_default.py \
  --work-dir work_dirs/my_dataset_dinov3 \
  --cfg-options \
    model.backbone.pretrained="$DINO_CKPT" \
    train_dataloader.dataset.data_root="$DATA_ROOT" \
    val_dataloader.dataset.data_root="$DATA_ROOT" \
    test_dataloader.dataset.data_root="$DATA_ROOT"

20.2 如果 sequence 名字不同¶

例如你的训练集是：

uavid_train/area001
uavid_train/area002
uavid_val/area101
uavid_test/area201

那么要改 dataset class 的读取规则，或者让文件夹命名继续使用 seq* 风格。当前 UAVIDDataset 并不强制名字必须是 seq*，但 check_uavid_dataset.py 当前检查脚本使用了：

split_dir.glob("seq*")

所以如果改成 area001，训练代码可通过 sequences=['area001'] 读取，但检查脚本也要相应改成更通用的目录扫描。

20.3 如果类别数量不同¶

假设新数据集有 5 类，需要改三个地方。

第一，改 mmseg/datasets/uavid.py：

METAINFO = dict(
    classes=('class_a', 'class_b', 'class_c', 'class_d', 'class_e'),
    palette=[
        [0, 0, 0],
        [255, 0, 0],
        [0, 255, 0],
        [0, 0, 255],
        [255, 255, 0],
    ],
)

第二，改 projects/UAVid_dataset/_base_/datasets/uavid.py 里的 uavid_palette，让 UAVidColorToId 能把 RGB label 转成新 class id。

第三，改主 config：

model = dict(
    decode_head=dict(num_classes=5),
    auxiliary_head=dict(num_classes=5),
)

20.4 如果标签已经是单通道 class id¶

如果 label 图是单通道，像素值已经是：

0, 1, 2, ..., num_classes - 1

那么 UAVidColorToId 会保持单通道 label，不会强制 RGB 转换。

仍然要保证：

ignore pixels = 255
valid class id = 0 到 num_classes - 1

20.5 如果标签是 RGB 彩色图¶

如果 label 是 RGB 彩色图，必须确保每种颜色都在 palette 中。

检查方式：

python tools/check_uavid_dataset.py /absolute/path/to/my_dataset

如果出现：

unknown label colors: {(12, 34, 56): 3}

说明标签里有 palette 外颜色。常见原因：

  • 标注软件导出时做了抗锯齿，边界出现中间色。
  • label 保存成 JPEG，压缩产生了新颜色。
  • palette 写错。
  • 标签颜色和 class id 对应关系不一致。

语义分割标签建议保存为 PNG，不建议保存为 JPEG。

20.6 先理解 MMSeg 配置文件的三层关系¶

在这个教程包里，很多修改不是直接写在 train.py 里，而是写在 config 里。理解 config 的层级之后，后面换数据集、换分割头、换类别数会清楚很多。

当前主配置是：

projects/UAVid_dataset/configs/vit_dinov3_uavid_512_default.py

它继承了三个 base config：

_base_ = [
    '../../_base_/models/uppernet_vit-b16.py',
    '../_base_/datasets/uavid.py',
    '../../_base_/default_runtime.py',
]

三类文件分别负责：

文件 负责内容 常见修改
projects/_base_/models/uppernet_vit-b16.py 模型结构，包括 DINOv3 backbone、neck、decode head、auxiliary head 换 UPerNet/FCN/PSP/SegFormer 等分割头
projects/UAVid_dataset/_base_/datasets/uavid.py 数据读取、pipeline、dataloader、evaluator 换数据路径、split、类别 palette、pipeline
projects/_base_/default_runtime.py 日志、hook、可视化、默认 runtime 通常不需要初学者修改
projects/UAVid_dataset/configs/vit_dinov3_uavid_512_default.py 当前实验的总入口，覆盖 base config 的关键字段 设置 DINOv3 权重、类别数、crop size、训练长度、sample data 路径

所以改造时不要优先改 train.py 或 test.py。更推荐：

模型结构变化 -> 改或新增 projects/_base_/models/*.py
数据集变化   -> 改或新增 mmseg/datasets/*.py 和 projects/*/_base_/datasets/*.py
实验入口变化 -> 改或新增 projects/*/configs/*.py

这样别人拿到代码后，可以继续使用标准 MMSeg 命令：

python train.py --config your_config.py
python test.py --config your_config.py --checkpoint your_checkpoint.pth

DINOv3 ViT-B backbone + Feature2Pyramid neck + UPerHead decode head + FCN auxiliary head

对应模型配置文件是：

projects/_base_/models/uppernet_vit-b16.py

当前核心结构：

model = dict(
    type='EncoderDecoder',
    backbone=dict(
        type='DINOv3ViT',
        dino_type='dinov3_vit16_base',
        patch_size=16,
        out_indices=1,
        return_class_token=False,
        n_storage_tokens=4,
        mask_k_bias=True,
        init_cfg=dict()),

    decode_head=dict(
        type='UPerHead',
        in_channels=[768, 768, 768, 768],
        in_index=[0, 1, 2, 3],
        pool_scales=(1, 2, 3, 6),
        channels=512,
        dropout_ratio=0.1,
        num_classes=6,
        norm_cfg=norm_cfg,
        align_corners=False,
        loss_decode=dict(
            type='CrossEntropyLoss', use_sigmoid=False, loss_weight=1.0)),
    auxiliary_head=dict(
        type='FCNHead',
        in_channels=768,
        in_index=2,
        channels=256,
        num_convs=1,
        concat_input=False,
        dropout_ratio=0.1,
        num_classes=6,
        norm_cfg=norm_cfg,
        align_corners=False,
        loss_decode=dict(

主配置里又覆盖了：

model = dict(

    auxiliary_head=dict(num_classes=8),
    backbone=dict(pretrained=pretrained, freeze=True, out_indices=1),
)

也就是说，base model 文件里原来写的 num_classes=6 会被主配置改成 num_classes=8。如果你新建自己的 config，也要保证最终 resolved config 里的 decode_head.num_classes 与数据集类别数一致。

  • train.py

  • DINOv3 checkpoint 文件
  • mmseg/datasets/uavid.py

同一个数据集

只比较不同 segmentation head

20.7.3 当前 DINOv3 输出给 head 的特征形态¶

当前模型不是直接把 DINOv3 token 扔给 head，而是经过：

DINOv3ViT -> 4 个 feature maps -> Feature2Pyramid -> decode_head

Feature2Pyramid 配置：

neck=dict(type='Feature2Pyramid', embed_dim=768, rescales=[4, 2, 1, 0.5])

直观理解：

DINOv3 输出 768 维特征
Feature2Pyramid 把它变成 4 个不同尺度的 feature maps
UPerNet/SegFormer 这类多尺度 head 可以同时使用 4 个尺度
FCN/PSP/ASPP 这类单尺度 head 通常只取其中一个尺度

因此更换 head 时最重要的是匹配：

in_channels
in_index
num_classes
align_corners
loss_decode

多尺度 head 常用：

in_channels=[768, 768, 768, 768]
in_index=[0, 1, 2, 3]

单尺度 head 常用：

in_channels=768
in_index=2

in_index=2 表示取第三个 feature map。这个不是唯一正确选择，也可以测试 in_index=1 或 in_index=3，但教程中建议先固定 2，因为它和当前 auxiliary head 的设置一致。

20.7.4 示例一：把 UPerNet 换成 FCNHead¶

FCNHead 是最简单的分割头，适合作为教学 baseline。它通常精度不如 UPerNet，但结构更容易讲清楚。

新增文件：

projects/_base_/models/fcn_dinov3_vit-b16.py

内容可以参考：

norm_cfg = dict(type='SyncBN', requires_grad=True)

model = dict(
    type='EncoderDecoder',
    pretrained=None,
    backbone=dict(
        type='DINOv3ViT',
        dino_type='dinov3_vit16_base',
        patch_size=16,
        out_indices=1,
        return_class_token=False,
        n_storage_tokens=4,
        mask_k_bias=True,
        init_cfg=dict()),
    neck=dict(type='Feature2Pyramid', embed_dim=768, rescales=[4, 2, 1, 0.5]),

        type='FCNHead',
        in_channels=768,
        in_index=2,
        channels=256,
        num_convs=2,
        concat_input=True,

        num_classes=8,
        norm_cfg=norm_cfg,
        align_corners=False,
        loss_decode=dict(
            type='CrossEntropyLoss', use_sigmoid=False, loss_weight=1.0)),
    auxiliary_head=None,
    train_cfg=dict(),

)

主 config 只需要继承这个新模型 base：

_base_ = [
    '../../_base_/models/fcn_dinov3_vit-b16.py',
    '../_base_/datasets/uavid.py',
    '../../_base_/default_runtime.py',

如果保留主配置里的：

model = dict(
    decode_head=dict(num_classes=8),
    auxiliary_head=dict(num_classes=8),
    backbone=dict(pretrained=pretrained, freeze=True, out_indices=1),
)

那么 auxiliary_head=None 会被 auxiliary_head=dict(num_classes=8) 覆盖坏掉。FCN 版本主 config 应改成：

model = dict(
    decode_head=dict(num_classes=8),
    auxiliary_head=None,
    backbone=dict(
        pretrained=pretrained,
        freeze=True,
        out_indices=1),
    test_cfg=dict(mode='slide', crop_size=(512, 512), stride=(256, 256)))

这是一个很容易出错的地方：如果新 head 不使用 auxiliary head，要在主 config 里显式保持 auxiliary_head=None。

20.7.5 示例二：把 UPerNet 换成 PSPHead¶

PSPHead 也是经典分割头，使用 pyramid pooling，但通常是单尺度输入。

新增：

projects/_base_/models/psp_dinov3_vit-b16.py

核心 head 可以写成：

decode_head=dict(
    type='PSPHead',
    in_channels=768,
    in_index=2,
    channels=512,
    pool_scales=(1, 2, 3, 6),
    dropout_ratio=0.1,
    num_classes=8,

    align_corners=False,

    type='FCNHead',
    in_channels=768,
    in_index=1,
    channels=256,
    num_convs=1,

  • PSPHead 有 pooling 分支，也会涉及 BatchNorm。
  • smoke training 时不要使用 batch size 1。
  • 如果显存不够，先降低 channels，例如从 512 改为 256。

20.7.6 示例三：把 UPerNet 换成 SegformerHead¶

SegformerHead 是轻量多尺度 head，适合讲“多尺度特征融合”。它可以继续使用 Feature2Pyramid 输出的 4 个尺度。

新增：

20.7.7 示例四：继续使用 UPerNet，但改轻量化参数¶

有时不是换 head，而是想让训练更快或更省显存。可以保留 UPerNet，只降低 head 宽度。

原配置：

decode_head=dict(
    type='UPerHead',
    channels=512,
    ...
)
auxiliary_head=dict(
    type='FCNHead',
    channels=256,
    ...
)

轻量版本：

decode_head=dict(
    type='UPerHead',
    channels=256,
    ...
)
auxiliary_head=dict(
    type='FCNHead',
    channels=128,
    ...
)

这样不改变整体框架，但会降低 head 计算量。代价是精度可能下降，尤其是小目标类别可能受影响。

20.7.8 如何注册自定义分割头¶

如果只使用 MMSeg 已经提供的 UPerHead、FCNHead、PSPHead、ASPPHead、SegformerHead，通常不需要自己注册，因为 MMSeg 已经注册好了。

如果你写了自己的 head，比如：

mmseg/models/decode_heads/my_simple_head.py

需要做三件事。

第一，在 head 文件里注册：

import torch
import torch.nn as nn

from mmseg.models.decode_heads.decode_head import BaseDecodeHead
from mmseg.registry import MODELS


@MODELS.register_module()
class MySimpleHead(BaseDecodeHead):
    def __init__(self, **kwargs):
        super().__init__(input_transform='multiple_select', **kwargs)
        self.fuse = nn.Conv2d(sum(self.in_channels), self.channels, kernel_size=1)
        self.cls_seg_layer = nn.Conv2d(self.channels, self.num_classes, kernel_size=1)

    def forward(self, inputs):
        feats = self._transform_inputs(inputs)
        target_size = feats[0].shape[2:]
        resized = [
            torch.nn.functional.interpolate(
                x, size=target_size, mode='bilinear', align_corners=self.align_corners)
            for x in feats
        ]
        x = torch.cat(resized, dim=1)
        x = self.fuse(x)
        return self.cls_seg_layer(x)

第二，在 mmseg/models/decode_heads/__init__.py 中导入：

from .my_simple_head import MySimpleHead

并把类名加入 __all__，如果该文件使用了 __all__：

__all__ = [
    ...
    'MySimpleHead',
]

第三，在 config 里使用：

decode_head=dict(
    type='MySimpleHead',
    in_channels=[768, 768, 768, 768],
    in_index=[0, 1, 2, 3],
    channels=256,
    dropout_ratio=0.1,
    num_classes=8,
    norm_cfg=norm_cfg,
    align_corners=False,
    loss_decode=dict(
        type='CrossEntropyLoss', use_sigmoid=False, loss_weight=1.0)),

也可以不改 __init__.py，而是在主 config 的 custom_imports 里加入：

custom_imports = dict(
    imports=[
        'mmseg.datasets.uavid',
        'tools.uavid_color_to_id',
        'mmseg.models.decode_heads.my_simple_head',
    ],
    allow_failed_imports=False,
)

教学包里更推荐使用 custom_imports，因为它能让读者在主 config 中直接看到“这个实验依赖了哪些自定义模块”。如果是正式维护一个完整 MMSeg fork，则可以同时在 __init__.py 中注册，风格更接近 MMSeg 原生代码。

20.7.9 更换 head 后必须检查的字段¶

每换一个 head，都检查下面这些字段：

decode_head.in_index
decode_head.channels
decode_head.num_classes
decode_head.loss_decode
auxiliary_head 是否需要

常见错误：

错误 表现 解决
num_classes 没改 loss 正常但类别数不对，测试指标异常 同时改 decode_head 和 auxiliary_head
单尺度 head 却写了 in_channels=[...] 初始化或 forward 报类型错误 单尺度 head 用 in_channels=768
多尺度 head 却写了 in_channels=768 forward 报输入数量或通道不匹配 多尺度 head 用 [768,768,768,768]

20.8.3 如果新数据集是 RGB 彩色标签¶

如果你的标签是 RGB 颜色，而不是单通道 class id，那么需要一个颜色转 id 的 transform。

当前教程已有：

tools/uavid_color_to_id.py

它的名字虽然叫 UAVidColorToId，但本质上是：

palette RGB color -> class id
unknown color -> ignore_index

你可以继续复用它，只要传入自己的 palette：

my_palette = [
    [0, 0, 0],
    [128, 0, 0],
    [128, 64, 128],
    [0, 128, 0],
    [0, 0, 128],
]

train_pipeline = [
    dict(type='LoadImageFromFile'),
    dict(type='LoadAnnotations', reduce_zero_label=False),
    dict(type='UAVidColorToId', palette=my_palette, ignore_index=255),
    dict(type='RandomCrop', crop_size=(512, 512), cat_max_ratio=0.75),
    dict(type='RandomFlip', prob=0.5),
    dict(type='PackSegInputs'),
]

如果要让命名更通用，可以复制一份：

tools/color_mask_to_id.py

并把类名改为：

@TRANSFORMS.register_module()
class ColorMaskToId:
    ...

然后在 config 中导入：

custom_imports = dict(
    imports=[
        'mmseg.datasets.my_remote_dataset',
        'tools.color_mask_to_id',
    ],
    allow_failed_imports=False,
)

pipeline 中使用：

dict(type='ColorMaskToId', palette=my_palette, ignore_index=255)

注意：如果标签已经是单通道 class id，不需要颜色转换。此时 pipeline 保持：

dict(type='LoadAnnotations', reduce_zero_label=False)

不要额外做 RGB palette 转换。

20.8.4 新数据集的类别数要同时改三处¶

假设新数据集有 5 类，必须同时检查：

第一，dataset class 的 METAINFO：

METAINFO = dict(
    classes=('background', 'building', 'road', 'vegetation', 'water'),
    palette=[
        [0, 0, 0],
        [128, 0, 0],
        [128, 64, 128],
        [0, 128, 0],
        [0, 0, 128],
    ],
)

第二，RGB label transform 里的 palette：

my_palette = [
    [0, 0, 0],
    [128, 0, 0],
    [128, 64, 128],
    [0, 128, 0],
    [0, 0, 128],
]

第三，模型 head 的类别数：

model = dict(
    decode_head=dict(num_classes=5),
    auxiliary_head=dict(num_classes=5),
)

如果没有 auxiliary head：

model = dict(
    decode_head=dict(num_classes=5),
    auxiliary_head=None,
)

这三处含义不同：

METAINFO.classes/palette: 用于 dataset 元信息、指标输出、可视化颜色
ColorToId palette: 用于把 RGB 标签转成训练用 class id
num_classes: 用于决定模型最后输出几个类别通道

三者必须一致。

20.8.5 reduce_zero_label 什么时候要开¶

教程中 UAVid 使用：

reduce_zero_label=False

因为 UAVid 的 class id 0 是合法类别 building，不能被忽略。

只有当你的数据集约定：

0 表示背景或无效区域，不参与训练
1,2,3,... 表示真实类别

并且你希望把原来的 1 类变成训练时的 0 类，才考虑：

reduce_zero_label=True

对于初学者，建议优先把数据整理成：

0,1,2,...,num_classes-1 都是合法类别
255 是 ignore
reduce_zero_label=False

这样最不容易混淆。

20.8.6 新数据集应配套一个检查脚本¶

不要等训练报错才发现数据问题。建议给每个新数据集准备一个检查脚本，至少检查：

image 是否有同名 label
image 和 label 尺寸是否一致
label 是否只有合法 class id 或合法 RGB palette
train/val/test 是否为空
每个类别像素数量是否极端不平衡

对于标准目录结构，可以参考：

python tools/check_uavid_dataset.py /absolute/path/to/my_dataset

但如果你的目录不是 uavid_train/seq*/Images，这个脚本也要改。不要拿 UAVid 检查脚本直接检查完全不同结构的数据集，然后误以为数据为空。

为了让别人更容易复现，建议新建一个项目目录，而不是把所有内容都塞进 UAVid_dataset。

例如：

projects/MyRemote_dataset/
  _base_/

20.9 最推荐的改造路线¶

如果你要把这套代码迁移到自己的任务，建议按下面顺序做，不要一次改太多。

第一步，只跑通 sample data：

第三步，确认自己的数据能训练、验证、测试之后，再换分割头：

crop_size

不要一开始同时修改：

否则一旦报错或精度差，很难判断问题来自哪里。

21.1 混淆矩阵直觉¶

对于每个像素，模型预测一个类别，标签提供真实类别。

如果真实是 road，预测也是 road：

correct

如果真实是 road，预测成 building：

wrong

把所有像素的预测和真实类别统计起来，就能得到每类的准确率、IoU 等指标。

21.2 Pixel Accuracy¶

总体像素准确率：

aAcc = all correctly predicted pixels / all labeled pixels

它的优点是直观，缺点是会被大面积类别主导。例如背景、道路、建筑占比很大时，即使 human、car 很差，aAcc 仍然可能很高。

21.3 Class Accuracy¶

某一类的 accuracy：

class accuracy = correctly predicted pixels of this class / ground-truth pixels of this class

平均类别准确率：

mAcc = mean(class accuracy)

21.4 IoU¶

IoU 是 Intersection over Union。

对某一类，例如 road：

intersection = 预测为 road 且真实也是 road 的像素
union = 预测为 road 的像素 + 真实为 road 的像素 - intersection
IoU = intersection / union

例子：

ground-truth road pixels = 100
predicted road pixels = 120
correct road pixels = 80
union = 100 + 120 - 80 = 140
road IoU = 80 / 140 = 0.571

21.5 mIoU¶

mIoU 是所有类别 IoU 的平均：

mIoU = mean(IoU_building, IoU_road, ..., IoU_background)

在语义分割论文和实验汇报里，mIoU 通常是最核心指标。

21.6 为什么小目标类别更难¶

UAVid 中 human、moving_car、static_car 往往面积较小。

小目标类别难点：

  • 像素数量少，训练信号少。
  • 目标容易被 512 crop 截断。
  • 目标边界细，标注误差影响更大。
  • 大尺度下采样后细节容易消失。

因此教学时不要只看 overall accuracy，也要看 per-class IoU。
